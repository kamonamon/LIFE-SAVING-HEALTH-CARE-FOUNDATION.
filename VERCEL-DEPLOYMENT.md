VERCEL DEPLOYMENT CHECKLIST - LIFE SAVING HEALTH CARE FOUNDATION

Status: Vercel-compatible static build and payment function wrappers are prepared and locally tested. An actual owner's Vercel deployment and live Relworx transaction have NOT been tested. Donations remain disabled by default.

1. DEPLOY TO THE EXISTING VERCEL PROJECT
- Unzip the client ZIP. Its inner LIFE-SAVING-HEALTH-CARE-FOUNDATION-main folder is the project root, containing index.html, package.json, vercel.json, api/, lib/, scripts/, assets/.
- Update the Git repository/branch connected to the owner's EXISTING Vercel project, or deploy its complete source folder with the owner's consent. Do not unintentionally create a new Vercel project.
- In Vercel Project Settings, confirm the correct Root Directory. If the repository contains a nested website folder, use that folder.
- vercel.json specifies Framework Other, Build Command npm run build, Output Directory public.
- The build generates public/ with only website assets. Server-side Relworx code remains outside public.
- api/payments/*.mjs are Vercel module-based function entrypoints; they load private handlers from lib/handlers/*.cjs.
- Do not upload only public/ - doing so excludes serverless payment endpoints.

2. VERIFY URLS AFTER DEPLOYMENT
- / and /index.html: homepage
- /about.html /insurance.html /blog.html /donate.html: pages
- GET /api/payments/config: provider relworx, ready false while disabled
- POST /api/payments/initiate: must return 503 until activated
- POST /api/payments/verify: server-side verification
- POST /api/payments/webhook: signed webhook acknowledgement
If /api/payments/config returns 404/500, check the Vercel build output, Root Directory, and Functions logs. This is not fixed by simply pasting API keys.

3. ADD ENVIRONMENT VARIABLES SECURELY
Owner/admin visits Vercel Dashboard > Existing Website Project > Settings > Environment Variables.
Use the correct Production or Preview target:
RELWORX_API_KEY       = private key from the foundation's Relworx merchant account
RELWORX_ACCOUNT_NO     = foundation's authorized Relworx business account number
RELWORX_INTENT_SECRET  = long random signing secret generated by developer
RELWORX_WEBHOOK_KEY    = Relworx business-account webhook authentication key
RELWORX_WEBHOOK_URL    = exact configured HTTPS URL, for example:
                         https://life-saving-health-care-foundation.vercel.app/api/payments/webhook
RELWORX_ENABLED        = false

Keep keys private. Do not expose them via HTML, source code, chat, screenshots or GitHub. Do not prefix secrets with NEXT_PUBLIC_ or VITE_.
ENVIRONMENT CHANGES REQUIRE A NEW DEPLOYMENT. Vercel does not retroactively apply new environment settings to existing deployments.

4. CONFIRM RELWORX AUTHORIZED SERVER IPs
Relworx may reject API requests from unauthorized server IPs (business settings: API Authorized IPs).
Standard Vercel Functions use rotating outbound IPs. Vercel Static IP networking is a separate paid Pro/Enterprise capability; do not assume a Hobby account has it.
Ask Relworx whether the account must authorize a fixed IP. Options may include eligible Vercel Static IP service or moving just the payment backend to a secure server with a fixed outbound IP. That networking decision is NOT solved by environment variables alone.

5. WEBHOOK AND TRANSACTION RECORDS
Register the EXACT RELWORX_WEBHOOK_URL under the business account settings, matching its key and all punctuation/slashes.
The current webhook validates a signature and acknowledges receipt. It does NOT save a permanent transaction ledger or issue automatic receipts. The owner should reconcile funds in the Relworx merchant dashboard. Full receipts, idempotency and audit reports require durable storage.

6. SAFE LIVE ACTIVATION
- Verify approved account, UGX collecting permissions, settlement recipient, fees, refunds, legal and privacy disclosures.
- Deploy with RELWORX_ENABLED=false and check all pages and /api/payments/config.
- Confirm allowed server IPs with Relworx.
- Arrange a controlled, provider-approved test or an owner-approved small real transaction.
- Only then change RELWORX_ENABLED=true and REDEPLOY, testing a genuine phone prompt and exact verified amount/status on the Relworx merchant dashboard.
- For incidents, set RELWORX_ENABLED=false and REDEPLOY.
- No real Relworx payment has been executed during development of this ZIP.
